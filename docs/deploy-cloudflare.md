# Публикация «Облаков» на своём Cloudflare

Сайт работает как Cloudflare Worker с базой D1. Вход — через Cloudflare Access:
человек вводит email и получает на него одноразовый код. Какие права у него на доске,
решает само приложение (админка «Пользователи и доступ»), а не Cloudflare.

Публикует GitHub Actions: при каждом изменении ветки `main` (или по кнопке
**Run workflow**) сайт собирается, проходят тесты, база получает миграции и
выкладывается новая версия. Всё ниже можно сделать с телефона в браузере.

Бесплатных тарифов Cloudflare (Workers, D1, Zero Trust до 50 пользователей) для одной доски хватает.

---

## 1. Cloudflare: аккаунт и ключ для GitHub

1. Зарегистрируйтесь на <https://dash.cloudflare.com>.
2. Откройте **Workers & Pages**. При первом входе Cloudflare попросит выбрать
   поддомен `workers.dev` — выберите любой. Адрес сайта будет
   `https://oblaka.<поддомен>.workers.dev`.
3. Скопируйте **Account ID**: он есть на странице Workers & Pages (справа или в меню
   «⋯») и в адресной строке: `dash.cloudflare.com/<Account ID>/…`.
4. Создайте API-токен: значок профиля → **My Profile** → **API Tokens** →
   **Create Token** → шаблон **Edit Cloudflare Workers** → **Use template**.
   - В **Permissions** нажмите **+ Add more** и добавьте `Account` · `D1` · `Edit`.
   - В **Account Resources** выберите свой аккаунт.
   - **Continue to summary** → **Create Token** → скопируйте токен (он показывается один раз).

## 2. GitHub: секреты и настройки

В репозитории: **Settings** → **Secrets and variables** → **Actions**.

Вкладка **Secrets** → **New repository secret**:

| Имя | Значение |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | токен из шага 1.4 |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из шага 1.3 |

Вкладка **Variables** → **New repository variable**:

| Имя | Значение |
| --- | --- |
| `OBLAKA_OWNER_EMAIL` | email, с которым вы будете входить. Этот человек — владелец (суперадминистратор). |

## 3. Первая публикация

**Actions** → **Deploy to Cloudflare** → **Run workflow** (ветка `main`).
Через 3–5 минут задача станет зелёной, а в её журнале (шаг **Deploy**) будет адрес сайта.

Сейчас сайт закрыт для всех и пишет «Войдите» — так и должно быть, пока не включён вход.

## 4. Включить вход (Cloudflare Access)

1. Откройте <https://one.dash.cloudflare.com> (Zero Trust). При первом входе
   придумайте имя команды — получится домен `<команда>.cloudflareaccess.com` —
   и выберите бесплатный план. Cloudflare может попросить привязать карту, даже для бесплатного плана.
2. В обычной панели: **Workers & Pages** → **oblaka** → **Settings** →
   **Domains & Routes** → у `workers.dev` нажмите **Enable Cloudflare Access**.
3. В Zero Trust: **Access** → **Applications** → откройте созданное приложение.
   - Скопируйте **Application Audience (AUD) Tag**.
   - Во вкладке **Policies** сделайте правило **Allow** с **Include** → **Everyone**.
     Это безопасно: Access лишь проверяет, что человек владеет email, а доступ к доске
     получают только те, кого вы добавили в админке.
   - Способ входа **One-time PIN** (код на почту) включён по умолчанию.
4. В GitHub (**Variables**) добавьте:

   | Имя | Значение |
   | --- | --- |
   | `ACCESS_TEAM_DOMAIN` | `<команда>.cloudflareaccess.com` |
   | `ACCESS_AUD` | AUD Tag из шага 3 |

5. Снова **Actions** → **Deploy to Cloudflare** → **Run workflow**.

Откройте адрес сайта, введите email владельца и код из письма — откроется доска с примерами.

Сайт проверяет подпись токена Access сам. Поэтому адрес, не закрытый Access
(например, preview-ссылка Workers), всё равно не пустит без входа.

## 5. Перенести доску со старого сайта

1. На **старом** сайте дождитесь, пока всё синхронизируется, затем меню слева →
   **Скачать копию доски**.
2. На **новом** сайте: меню → **Пользователи и доступ** → **Перенести доску** →
   **Выбрать файл копии**. Доска целиком заменится содержимым файла.
3. Там же добавьте участников заново (email и права): аккаунты на новом сайте другие.
4. На телефоне удалите старую иконку с экрана «Домой» и добавьте новый сайт
   (Safari → «Поделиться» → «На экран Домой»), откройте его один раз с интернетом —
   после этого он работает и офлайн.

## Обновления

Любое изменение в ветке `main` публикуется само. Повторить публикацию вручную:
**Actions** → **Deploy to Cloudflare** → **Run workflow**.

Настройки сайта (email владельца, Access) меняются только в GitHub **Variables** с
последующей публикацией: значения, заданные вручную в панели Cloudflare, публикация перезапишет.

## Что не перенесено

- **Чтение доски из ChatGPT (MCP)** работало через Sites; на этом хостинге ChatGPT не сможет войти.
- **Одноразовый импорт из Todoist** (`/api/import-todoist`) выключен, пока не заданы его секреты.

## Локальная разработка

`npm run dev`, затем `http://127.0.0.1:5173/signin-with-chatgpt?return_to=/` —
тестовый вход, который работает только на этом компьютере и не попадает в сборку.
